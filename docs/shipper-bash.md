# Bash shipper (Linux without Docker)

For Debian/Ubuntu VPS with root access but no Docker. The `scripts/install-shipper.sh` script is self-contained — it embeds the 9 Alloy modules + the renderer, installed via `curl | sudo bash`.

## Prerequisites

- Debian / Ubuntu with systemd (tested Debian 12, should work on Ubuntu 22+)
- Root access (sudo)
- Outbound network (apt, ghcr, your `LOGS_DOMAIN`)

## One-liner install (managed mode)

```bash
INGEST=<INGEST_AUTH_TOKEN>
REGISTER=<WGR_API_REGISTER_TOKEN>

curl -sSL https://raw.githubusercontent.com/wgr-sa/wgr-logs/main/scripts/install-shipper.sh \
  | sudo bash -s -- \
      --api-url https://<LOGS_DOMAIN>/mgmt \
      --register-token "$REGISTER" \
      --ingest-token "$INGEST" \
      --ingest-url https://<INGEST_DOMAIN>/loki/api/v1/push \
      --name $(hostname)
```

What the script does:
1. `apt install jq curl gnupg acl alloy` (Grafana repo)
2. Extracts the embedded 9 Alloy modules + render.sh
3. `POST /mgmt/agents/register` → gets `agent_id` + `agent_token`
4. Saves tokens to `/var/lib/wgr-shipper/agent.json` (chmod 600)
5. Creates 2 systemd services:
   - `alloy.service` (apt package, already provided)
   - `wgr-shipper-poll.service` (custom, handles polling + reload)
6. Enables and starts both

## Static mode install

Without an API, with a local sources.json:

```bash
# Prepare sources.json
sudo mkdir -p /etc/wgr-logs && sudo nano /etc/wgr-logs/sources.json
# Content: { "defaults": {...}, "sources": [...] }

curl -sSL https://raw.githubusercontent.com/wgr-sa/wgr-logs/main/scripts/install-shipper.sh \
  | sudo bash -s -- \
      --ingest-token "$INGEST" \
      --ingest-url https://<INGEST_DOMAIN>/loki/api/v1/push \
      --sources-file /etc/wgr-logs/sources.json
```

## Installed layout

```
/etc/alloy/
├── .env                          (chmod 600): WGR_INGEST_URL, WGR_INGEST_USER, WGR_INGEST_TOKEN
├── config.alloy                  (generated by renderer at boot, regenerated on each config change)
└── modules/                      (9 .alloy files, extracted by the script)

/etc/systemd/system/
├── alloy.service.d/wgr-env.conf  (drop-in: EnvironmentFile=/etc/alloy/.env)
└── wgr-shipper-poll.service      (managed mode only)

/usr/local/bin/
├── wgr-shipper-render            (render.sh, JSON → config.alloy)
└── wgr-shipper-poll              (managed mode only, polling loop)

/var/lib/wgr-shipper/
├── agent.json                    (chmod 600): { agent_id, agent_token, status }  (managed mode only)
├── last-etag                     (last known ETag)                                (managed mode only)
└── sources.json                  (cache of the last received config)              (managed mode only)
```

## Managed flow

```
every 60s:
  wgr-shipper-poll → curl /mgmt/agents/<id>/config (Bearer agent_token)
                   ← ETag + rendered config
  
  if ETag changed:
    → wgr-shipper-render → /etc/alloy/config.alloy
    → systemctl reload alloy
```

## View logs

```bash
# Alloy (the agent that ships logs)
sudo journalctl -u alloy -n 50 -f

# The poller (managed loop)
sudo journalctl -u wgr-shipper-poll -n 50 -f

# Status
sudo systemctl status alloy wgr-shipper-poll
```

## Permissions (ACL)

Alloy runs as the `alloy` user. To let it read app logs (e.g. PM2, CakePHP), grant ACL:

```bash
# Example PM2 (owner: debian)
sudo setfacl -m u:alloy:rx /home/debian /home/debian/.pm2 /home/debian/.pm2/logs
sudo setfacl -m u:alloy:r  /home/debian/.pm2/logs/*.log 2>/dev/null
sudo setfacl -d -m u:alloy:r /home/debian/.pm2/logs

# Example CakePHP / WordPress under /var/www
sudo setfacl -R -m u:alloy:rX /var/www
sudo setfacl -d -R -m u:alloy:rX /var/www
```

If the agent reports 0 logs for a given source type, this is usually a missing ACL.

## Update (new script version)

Re-run the `curl | sudo bash`:
- Modules + render.sh are rewritten with the new version
- `agent.json` is preserved (no re-enrolment)
- Script restarts both services

## Uninstall

```bash
sudo bash install-shipper.sh --uninstall
```

Effect:
- Stops + disables `wgr-shipper-poll`
- Removes `/etc/alloy/modules/`, `config.alloy`, `.env` drop-in, `/usr/local/bin/wgr-shipper-*`
- **Keeps**: the `alloy` package (apt), the state `/var/lib/wgr-shipper/`, the Grafana apt repo

Full cleanup:
```bash
sudo apt purge -y alloy
sudo rm -rf /etc/apt/sources.list.d/grafana.list /etc/apt/keyrings/grafana.gpg
sudo rm -rf /var/lib/wgr-shipper
```

The agent stays in the API DB. Remove via the desktop UI if desired.

## Typical use case: migrate a manually-installed Alloy

If you previously installed Alloy by hand (old patterns), you can migrate:

```bash
# 1. Stop the old service
sudo systemctl stop alloy

# 2. Backup the old config
sudo cp /etc/alloy/config.alloy /root/old-alloy-config.alloy.bak

# 3. Run the new installer (managed mode)
curl -sSL .../install-shipper.sh | sudo bash -s -- \
  --api-url https://<LOGS_DOMAIN>/mgmt \
  --register-token "$REGISTER" \
  --ingest-token "$INGEST" \
  --ingest-url https://<INGEST_DOMAIN>/loki/api/v1/push \
  --name $(hostname)

# 4. In the desktop UI, the agent appears. Add the sources that the old config had.
```

## Debug

| Symptom | Diagnosis |
|---|---|
| `Registration failed` | Invalid `--register-token`, check it in the wgr-logs server `.env` |
| `Alloy not running` after install | `journalctl -u alloy -n 50` — often a syntax error in the rendered config, or a missing mount |
| Agent visible in UI but 0 logs | Missing ACL server-side (`alloy` user can't read the files) |
| Reload not picked up | `sudo systemctl reload alloy` manually, then check `journalctl -u alloy --since "1 min"` |
